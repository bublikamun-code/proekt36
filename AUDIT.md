## 1. Что это за проект

Полностью клиентское SPA (Vue 3 + TypeScript + Vite + Pinia) для 2D-компоновки распределительных
электрощитов. Бэкенда нет by design: данные живут в localStorage/IndexedDB браузера,
«бэкенд-слой» — это чистый доменный TypeScript (`src/domain/`, ~6 000 строк) и локальный
AI-прокси на Node (`tools/ai-proxy.mjs`). PWA с офлайн-оболочкой.

### Docker

Dockerfile, `nginx-default.conf`, docker-compose.yml и .dockerignore **добавлены в репозиторий**
(multi-stage: `node:22-alpine` → сборка → `nginx:1.27-alpine` на 8080, SPA-fallback,
кэш-заголовки, CSP заголовком, read_only + no-new-privileges в compose). Запуск на любой
обычной машине:

```bash
docker compose up --build   # → http://localhost:8080
```

nginx-конфиг вынесен в отдельный файл `nginx-default.conf` (не `printf` внутри Dockerfile —
так читабельно и не зависит от поведения printf в alpine) и **проверен живым nginx 1.26**:
`nginx -t` — синтаксис OK; отдача `/` — 200 с CSP/X-Content-Type-Options/Referrer-Policy
заголовками; SPA-fallback `/some/deep/route` — 200 (index.html); `sw.js` — no-cache.

**Важно:** в текущей песочнице сам образ собрать/запустить невозможно — среда сама является
непривилегированным контейнером (нет `CAP_SYS_ADMIN`, seccomp-фильтр; `unshare: operation not
permitted` на любой распаковке слоя). Это ограничение среды, не проекта. Содержимое образа
эквивалентно проверенному локально пути `npm ci && npm run build` + статика через nginx.

## 3. Архитектура и код (бэкенд/домен-слой)

**Сильно.** Оценка: 9/10.

- Чистое разделение: `domain/` (логика без Vue), `stores/` (Pinia), `storage/` (репозиторий),
  `components/`, `views/`. Домен покрывается юнит-тестами напрямую.
- Валидация проекта — собственная строгая схема (`projectSchema.ts`) с лимитами
  (`PROJECT_LIMITS`: 500 устройств, 2000 связей, лимиты длин строк), версионирование схемы
  (v1→v2 миграция), отклонение неизвестных ревизий.
- Хранилище продумано лучше, чем у большинства продакшн-проектов: атомарная запись пачки ключей
  через write-journal (`panel36.storage.journal.v1`) с replay при старте, recovery-снапшоты при
  порче данных, отдельные сообщения на QuotaExceeded/SecurityError, debounced autosave 200 мс
  с flush на `pagehide`.
- Undo/redo: на проект, лимит 50, коалесинг повторов (зажатие стрелки = один шаг истории).
- CAD-импорт: лимиты (50 МБ модель, 100 МБ распакованного ZIP, 256 записей, анти-zip-bomb
  коэффициент 1000:1), запрет абсолютных путей и traversal, модели именуются по id.
- AI-ассистент: браузер шлёт только агрегированный контекст (`assistantContext.ts` — одно
  аудируемое место), ключ живёт только в локальном прокси на 127.0.0.1, тело запроса не логируется.

### Замечания домена

1. ~~**`clone()` через `JSON.parse(JSON.stringify())`**~~ → **исправлено**: `structuredClone()`
   с честным снимком прокси (`toRaw`) в сторе и JSON-фоллбеком для структур, в которых всё ещё
   живут reactive-прокси (устройство может прийти прямо из reactive-каталога — `structuredClone`
   такие отказывается клонировать, тесты это поймали).
2. **История undo хранит полные копии проекта** — 50 × полный проект в памяти. Для текущих
   объёмов приемлемо, но стоит держать в голове при росте лимитов.
3. **`fsync`-аналога у localStorage нет** — журнал это компенсирует, ок.

## 4. Фронтенд

Оценка: 8/10.

- Vue 3 Composition API везде, `defineAsyncComponent` для тяжёлого 3D-превью — правильный
  подход к 613 КБ чанку с three.js.
- Роутер: ленивые импорты всех view, guard'ы аккуратные, open-redirect закрыт через

  стоит резать на композаблы/подкомпоненты до того, как пойдёт новая фича.
- Крупный чанк `ModelPreview` (613 КБ) вынесен, но подгружается `defineAsyncComponent` без
  отображения состояния загрузки — при медленной сети кнопка выглядит мёртвой. Мелкий UX-штрих:
  добавить loading-state.

## 6. Безопасность

Оценка: 8.5/10 (для локального приложения с «бэкендом в браузере» — почти образцово).

**Сделано правильно:**
- CSP вшивается в прод-сборку: `script-src 'self'`, `object-src 'none'`, `worker-src 'self'`,
  без CDN и внешних шрифтов; `frame-ancestors`/`form-action` честно задокументированы как
  требующие заголовков (meta их игнорирует).
- **Ни одного XSS-приёмника**: нет `v-html`, `innerHTML`, `eval` по всему `src/`.
- Единственный `target="_blank"` имеет `rel="noreferrer"`.
- Секретов в репо нет: `tools/ai-proxy.env` в .gitignore, только `.example`; пароли не
  сохраняются нигде (демо-вход пишет в sessionStorage только email/имя и честно об этом говорит).
- AI-прокси: слушает только 127.0.0.1, whitelist origin, лимит тела 256 КБ, таймауты, никакой
  телеметрии.
- ZIP-импорт: защита от zip-бомб, path traversal, лимиты количества и размера.

**Риски и рекомендации:**
1. ~~**`npm audit`: 1 high — `source-map-js`**~~ → **исправлено**: lock обновлён (`npm audit fix`),
   `npm audit` в runtime-зависимостях чистый.
2. ~~**AI-прокси не имеет rate-limit**~~ → **исправлено**: sliding-window лимит на `/chat`
   (10 запросов / 60 с по умолчанию, настраивается `AI_PROXY_RATE_LIMIT`/`AI_PROXY_RATE_WINDOW_MS`),
   превышение — 429 с человекочитаемым сообщением. Проверено живым прокси: 3 пропущенных → 429.
3. **CSP `style-src 'unsafe-inline'`** — вынужденно (инлайн-геометрия доски), задокументировано.
4. ~~**CSP через meta-тег**~~ → **исправлено**: nginx в Docker отдаёт тот же CSP заголовком
   (включая `frame-ancestors 'none'` и `form-action 'self'`) на все ответы, конфиг проверен
   живым nginx.
5. **Демо-«авторизация» — это UI-фильтр, а не защита.** Она так и задумана (сессия в sessionStorage),
   но при появлении настоящего бэкенда весь `/app/**` нужно защищать серверно, не по флагу в сторе.
6. `robots.txt` корректно закрывает `/app`, `/login`, `/register`, `/demo/project` (noindex
   демо-доски дублирован — осознанно, т.к. тег ставится скриптом после первого paint).

## 7. Стабильность и тесты

Оценка: 8.5/10.

- **245 юнит-тестов + 120 e2e + 3 preview-smoke — все зелёные.** Покрытие по-настоящему
  содержательное: миграции схемы, квоты/повреждение хранилища, транзакционность записи,
  контрасты, e2e на печать, клавиатуру, deep links прод-сборки.
- CI (`.github/workflows/verify.yml`) гоняет тот же `npm run verify`, что и локально —
  определение «работает» одно на все среды. Это правильная дисциплина.
- **Visual-снапшоты: исправлено добавлением `maxDiffPixelRatio: 0.01`.** Диагностика: на свежей
  базовой линии (обновлена в 16ffce6) любая другая Linux-машина давала расхождение 0.004–0.01
  ratio чисто из-за антиалиасинга/хинтинга шрифтов (проверено: установка `fonts-liberation`
  убрала макро-различия, остались субпиксельные). Порог 1% поглощает шум рендера, но любой
  реальный сдвиг макета всё ещё валит тест. Базовые линии из репозитория не менялись — CI
  остаётся совместим.
- ~~Расхождение host'а dev-сервера и e2e~~ → **исправлено**: `"dev": "vite --host 127.0.0.1"`,
  плюс в `vite.config.ts` закреплены `host 127.0.0.1`, `port 5173`, `strictPort: true` — dev,
  e2e и preview теперь гарантированно говорят об одном адресе.
- Сборка быстрая (1.3 с), HMR живой; единственный warning — чанк three.js > 500 КБ (осознанно
  вынесен, можно поднять `chunkSizeWarningLimit` или добавить manualChunks-группировку).

## 11. Проверка живого деплоя (Docker на хосте, 2026-10-06)

Деплой поднят пользователем: `http://192.168.0.119:8080` (LAN) / `http://172.17.0.1:8080`
(docker bridge). Проверено извне, без доступа к хосту.

**Зелёное:**

| Проверка | Результат |
|---|---|
| Оба адреса | ✅ 200 |
| **Полный e2e-набор против деплоя** | ✅ **120/120** (`playwright.deploy.config.ts`, включает все 5 visual-тестов) |
| Главная и демо-доска визуально | ✅ рендер корректный, доска/панель/устройства на месте |
| SPA deep links (`/app`, `/app/editor`, `/demo/project`) | ✅ 200 |
| PWA: manifest, иконки, favicon, offline.html | ✅ 200 |
| Модель `/models/city9-mcb-2p.glb` | ✅ 200, `Cache-Control: immutable` |
| Ассеты | ✅ 200, immutable-кэш, gzip включён |
| `sw.js` | ✅ `no-cache` |

**Находки:**

1. **Контейнер работает со СТАРЫМ nginx-конфигом — заголовки безопасности отсутствуют.**
   Ответы отдаются без `Content-Security-Policy`, `X-Content-Type-Options`,
   `Referrer-Policy` заголовков (ETag-стиль и набор заголовков соответствуют
   промежуточной версии Dockerfile до коммита 5733608). Приложение внутри при этом
   свежее: CSP meta-тег в HTML есть, поэтому базовая защита (script-src 'self' и т.д.)
   действует; не действуют только `frame-ancestors`/`form-action`, которые meta не умеет.
   **Как чинить:** пересобрать образ из текущего main —
   `git pull && docker compose up -d --build` (в репо теперь `nginx-default.conf`,
   Dockerfile его копирует).
2. **AI-ассистент по LAN/IP-адресу работать не будет** — это ожидаемо, но стоит знать:
   - CSP `connect-src` разрешает только `127.0.0.1:8787`/`localhost:8787`;
   - прокси whitelist'ит только `127.0.0.1`/`localhost` Origin (403 на прочие).
   При открытии панели по `192.168.0.119:8080` (или с другого устройства LAN) запросы
   ассистента будут блокированы. Осознанный компромисс «ключ не покидает хост».
   Если LAN-доступ к ассистенту понадобится: добавить адрес в whitelist
   `tools/ai-proxy.mjs` (`allowedOrigin`) И в `connect-src` (vite.config + nginx-default.conf),
   но тогда прокси надо слушать не только loopback — решение за вами, это ослабляет безопасность.

Проверки деплоя повторяются командой:
`npx playwright test --config=playwright.deploy.config.ts` (цель настраивается `DEPLOY_URL`).
