# Панель 36 — локальный preproduction

Браузерное приложение для предварительной 2D-компоновки демонстрационных распределительных щитов. Эта версия полностью работает на устройстве пользователя: серверной авторизации, синхронизации, API, оплаты и загрузки пользовательских файлов нет.

> Расчёты, BOM и диагностика предварительные. Они не являются проектной документацией, сметой, публичной офертой или подтверждением нормативного соответствия.

## Быстрый старт

Требования: Node.js 22.12+ и современный браузер на базе Chromium, Firefox или WebKit с включёнными `localStorage` и `IndexedDB`.

```bash
npm install
npm run dev
```

Vite откроет локальный адрес, обычно `http://127.0.0.1:5173`.

Основные маршруты:

- `/` — публичная главная;
- `/features` — возможности;
- `/pricing` — тарифы;
- `/demo/project` — отдельный DEMO-проект, доступный только для чтения;
- `/app/projects` — локальная рабочая область;
- `/app/projects/:projectId/editor` — 2D-редактор конкретного проекта.

## Что проверить в браузере

Маршруты для ручной проверки. Свои изменения стоит смотреть не на главной, а там, где
они видны.

**Проверка нагрузки по фазам.** Правило срабатывает только на трёхфазном щите, где цепи
объявлены настоящими токами. Чтобы воспроизвести:

1. `/app/projects` → «Продолжить локально» → создать панель мастером → открыть редактор.
2. В инспекторе, раздел «Параметры панели»: «Фаза» → `L1, L2, L3`, «Вводной ток» → `20`.
3. Поставить на доску автомат, УЗО или дифавтомат (категории `MCB`, `RCCB`, `RCBO` в каталоге).
   Кнопка «＋ Цепь» активна только при наличии устройства, а сама цепь без защитного аппарата не
   создаётся.
4. «Цепи и подключения» → «＋ Цепь» три раза. В каждой цепи «Ток, А» → `10`, «Фаза» →
   `L1`. Сумма по L1 получается 30 А при вводном 20 А.
5. В списке проблем инспектора появляется «Нагрузка на L1 выше вводного». Снизить ток цепей до
   `5` — предупреждение исчезает.

Не задавайте цепи на щите без аппаратов: при отсутствии цепей приложение считает нагрузку как
сумму номиналов защит и намеренно не сравнивает её с вводным, потому что сумма номиналов
автоматов нагрузкой не является. Проверка на это есть в `tests/validation.test.ts`.

**Статус позиции каталога.** В редакторе, левая панель:

- у 111 позиций из 385 стоит метка: 72 с надписью «Шаблон», 39 с надписью «Статус не
  указан» (у встроенного каталога поле статуса просто отсутствует) и по одной на каждый
  импорт CAD;
- «Только проверенные» сужает список с 385 позиций до 274, меток на оставшихся нет;
- переключите тёмную тему: метка остаётся читаемой, она сделана заливкой и рамкой.

**Доска и маркировка.** В редакторе поставить аппарат на один модуль и убедиться, что адрес
(`QF00`) не превращается в многоточие. На печати проверяется отчёт `Печать` — он собирается на
A3 альбомной и не зависит от темы.

**Увеличение в рабочей области.** Редактор открывается вписанным в область щитом, кнопка
«Вписать» при этом нажата. Что проверить:

1. Нажать «＋» — процент перестаёт быть произведением двух величин и растёт на 10 пунктов от
   текущего, кнопка «Вписать» становится неактивной.
2. Нажать «Панели» и обратно — процент и размер щита не меняются. Раньше ручной зум умножался
   на коэффициент вписывания, и цифра на экране менялась сама.
3. Колесо с Ctrl (⌘ на macOS) над доской масштабирует её вокруг курсора; без Ctrl колесо
   прокручивает как обычно.
4. Увеличить до 200–300 % и увести щит вбок — прокруткой доступна вся доска, левая половина не
   уезжает за пределы области.
5. Обновить страницу (F5) — выбранный масштаб сохранится; «Вписать» возвращает автоматический
   режим, и после перезагрузки он останется.

**Обновление страницы.** Обновление — это пауза, а не перезапуск: пользователь должен вернуться на
тот же щит, с тем же масштабом и с теми же открытыми панелями. Что проверить:

1. Открыть редактор, нажать «Панели», увеличить щит и обновить страницу (F5) — адрес не
   изменится, панели останутся открытыми, процент масштаба тем же.
2. Закрыть панели кнопкой «Только щит» и обновить страницу — редактор снова откроется один щит.
3. Пройти на `/app/editor` в чистом профиле (например, в приватном окне, где ещё ничего не
   создано), обновить страницу и убедиться, что вы остались в редакторе, а не на списке проектов.
   Раньше стартовый щит получал новый идентификатор при каждой загрузке, и ссылка на него
   переставала существовать.

**Визуальные эталоны.** `npx playwright test tests/e2e/visual.spec.ts` сверяет главную, щит в
режиме чтения, тот же щит в тёмной теме и доску редактора с PNG в
`tests/e2e/visual.spec.ts-snapshots`. Шрифты входят в сборку, но сглаживание зависит от ОС, поэтому
имена эталонов содержат платформу; на другой системе нужен свой эталон, а не починка текущего.
Эталоны для macOS записаны до исправления отрисовки лицевых панелей, поэтому их нужно переснять на
машине с macOS:

```bash
npx playwright test tests/e2e/visual.spec.ts --update-snapshots
```

## Проверка релиза

```bash
npm run verify
```

Команда последовательно выполняет:

1. `npm run typecheck`;
2. `npm test`;
3. `npm run test:e2e`;
4. production build;
5. smoke-тест direct deep links через `vite preview`.

Отдельные команды:

```bash
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run test:preview
```

## Версия и выпуск релиза

Версия приложения написана в коде в одном месте — `src/version.ts`. Из неё берутся:

- `APPLICATION_REVISION` в `src/domain/projectSchema.ts`;
- поля `application.revision` и `applicationRevision` в конверте экспорта `.panel36.json`;
- подпись в подвале публичных страниц.

Второе место, поле `version` в `package.json`, нужно самому npm. Расхождение между ними
ловит `tests/app-version.test.ts`, который входит в `npm test`.

Поднять версию и выпустить релиз:

```bash
npm run verify        # должен завершиться без ошибок
npm version 0.2.0     # minor — новая функциональность или смена схемы/каталога/проверок
# поставить то же значение в src/version.ts
# дописать раздел в CHANGELOG.md
git commit -am "release: 0.2.0"
git tag -a v0.2.0 -m "0.2.0"
```

История изменений: [`CHANGELOG.md`](CHANGELOG.md). Полный порядок выпуска и его ограничения —
в разделе 10 runbook.

## ИИ-помощник по сборке щита

Помощник отвечает по сводке щита (занятость, токи по фазам, сработавшие проверки) и может предложить изменение настроек из белого списка. Ключ провайдера в браузере не нужен — он хранится в локальном прокси:

```bash
cp tools/ai-proxy.env.example tools/ai-proxy.env   # заполнить AI_API_KEY
npm run ai
```

Приложение полностью работоспособно без прокси: в этом случае панель помощника показывает состояние «прокси не отвечает» и команду запуска. Название проекта и аппаратов, адреса, примечания, цепи и CAD-модели наружу не отправляются — состав сводки задан в `src/domain/assistantContext.ts` и проверяется тестами. Подробности: [`docs/PREPRODUCTION_RUNBOOK.md`](docs/PREPRODUCTION_RUNBOOK.md), раздел 7.

## Локальные данные

- Проекты, текущий проект и резервные снимки хранятся в `localStorage`.
- Импортированные GLB/glTF/ZIP хранятся локально в `IndexedDB`.
- DEMO не создаёт `sessionStorage`, пользовательские проекты или записи IndexedDB.
- Очистка данных сайта, приватный режим или смена браузера могут удалить локальное состояние.
- Для переноса используйте экспорт проекта либо резервную копию.

Резервная копия восстанавливает список проектов только после явного подтверждения. Если проект зависит от импортированной CAD-модели, её бинарные данные в JSON не входят; restore отклонит такую копию, чтобы не создать проект с молчаливо потерянной геометрией.

## Экспорт

- `.panel36.json` содержит проект, ревизии приложения/схемы/каталога/проверок, snapshot каталога и manifest локальных CAD-моделей.
- `panel36-backup-YYYY-MM-DD.json` содержит несколько проектов, выбранный проект и manifest локальных моделей.
- GLB/glTF/ZIP не встраиваются в JSON и не отправляются во внешние сервисы.

Полный runbook, лимиты и условия развёртывания: [`docs/PREPRODUCTION_RUNBOOK.md`](docs/PREPRODUCTION_RUNBOOK.md).
