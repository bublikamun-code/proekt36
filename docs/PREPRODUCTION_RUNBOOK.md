# Runbook локального preproduction «Панель 36»

## 1. Границы версии

Версия пригодна для локальной демонстрации, UX-проверки и предварительной подготовки 2D-компоновки. Она не содержит серверной учётной записи, синхронизации между устройствами, серверных прав доступа, оплаты, checkout, webhooks и публичного API.

Основной режим редактора — 2D. Полноценный 3D-редактор и 3D Viewer не являются частью релиза. Город9 остаётся отдельным тестовым образцом и не объединяется с официальными позициями ENMAS/CHINT. NB1-63DC исключён.

## 2. Запуск

```bash
npm install
npm run dev
```

Production-сборка и локальный просмотр:

```bash
npm run build
npm run preview
```

`vite preview` проверяет собранные статические файлы, но не заменяет настройку будущего CDN или web-сервера.

## 3. Проверки

```bash
npm run verify
```

Для диагностики запускайте этапы отдельно. Playwright использует Chromium; перед первым запуском при необходимости установите браузер командой `npx playwright install chromium`.

Проверки охватывают:

- TypeScript и Vue templates;
- schema v1 → v2, недействительные импорты и ссылки;
- footprint, транзакционные команды и миграцию корпуса;
- localStorage/IndexedDB, quota/security errors и per-project undo/redo;
- неизвестные цены и безопасный CSV;
- DEMO без локальных побочных эффектов;
- маршруты, диалоги, клавиатуру, печать и production deep links.

## 4. Хранение и восстановление

### Основные хранилища

| Данные | Хранилище | Примечание |
|---|---|---|
| Проекты и текущий проект | `localStorage` | Только в текущем браузере и origin |
| Последний валидный снимок | `localStorage` | Используется при повреждении основного снимка |
| Повреждённый исходный JSON | `localStorage` recovery key | Не удаляется молча при следующей записи |
| GLB/glTF/ZIP | `IndexedDB` | Бинарные данные остаются на устройстве |
| DEMO | Не использует пользовательские хранилища | Только детерминированный fixture |

При `QuotaExceededError`, `SecurityError` или блокировке хранилища интерфейс показывает actionable-состояние. Данные, которые не удалось записать, следует экспортировать вручную.

### Экспорт проекта

Кнопка «Экспорт» создаёт `.panel36.json`. Конверт включает:

- `application` и `applicationRevision`;
- `schemaRevision`;
- `catalogRevision` и snapshot каталога;
- `validationRevision`;
- полный объект `project`;
- `cadModelManifest` и `cad.binaryIncluded: false`.

Импортируются raw-проекты v1/v2 и поддерживаемые конверты. Будущие версии схемы и неизвестные ревизии отклоняются с сообщением пользователю.

### Резервная копия

Кнопки «Создать копию» и «Восстановить» работают с `panel36.backup.v1`. Восстановление заменяет текущий список проектов и сбрасывает их историю, поэтому перед подтверждением показывается отдельный диалог. Локальная библиотека CAD-моделей не удаляется.

Если проекты в копии ссылаются на импортированные модели, которых нет в catalog snapshot, восстановление блокируется: JSON не содержит GLB/glTF/ZIP. Это предотвращает тихую потерю геометрии. Храните такие проекты как отдельный архив до очистки браузера.

## 5. Ограничения CAD

- GLB: до 50 МБ, glTF 2.x.
- Автономный JSON glTF: до 50 МБ, внешние `buffer`/`image` запрещены.
- ZIP: до 50 МБ сжатого и до 100 МБ распакованного содержимого, не более 256 записей.
- Запрещены абсолютные и выходящие за пределы архива пути.
- Файлы проверяются и сохраняются только в IndexedDB браузера.
- Пользовательские данные не отправляются на сервер или во внешние сервисы.

Валидация файла не заменяет проверку геометрии, материалов, единиц, авторских прав и производственной пригодности модели.

## 6. Расчёты и печать

Приложение выполняет предварительную компоновку и поддерживаемые диагностические правила. Проверяются, в частности, переполнение рядов, пересечения, отсутствующие товары, ссылки цепей/подключений, дубли, базовая согласованность L/N/PE и фаз.

Не выполняются полноценные расчёты селективности, термического режима, КЗ/УЗ, нагрузочной способности, компенсации реактивной мощности, заземления и нормативного проектирования.

Печатный отчёт содержит компоновку, позиции, соединения как диагностические связи, BOM, проверки, ревизии и disclaimer. Он не является принципиальной схемой или монтажной документацией.

Цена `0` и неизвестная цена — разные состояния. Если цена не подтверждена, интерфейс показывает «уточняется» и не объявляет коммерческую сумму.

## 7. ИИ-помощник по сборке щита

Помощник отвечает по **сводке** щита и может предложить ограниченный набор изменений настроек. Ключ провайдера в браузере не хранится: запросы идут на локальный прокси, и уже он обращается к провайдеру.

Запуск в отдельном терминале:

```bash
cp tools/ai-proxy.env.example tools/ai-proxy.env   # заполнить AI_API_KEY
npm run ai
```

Прокси слушает только `127.0.0.1:8787`, принимает только origins вида `http://127.0.0.1:*` или `http://localhost:*`, ограничивает тело запроса 256 КБ и не пишет содержимое запросов в журнал. Поддерживаются провайдеры `anthropic` и `openai`; выбор делается переменными `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`, необязательными `AI_BASE_URL` и `AI_PORT`.

Панель помощника находится внизу инспектора. Если прокси не запущен или в нём не задан ключ, панель показывает это состояние и команду запуска, а не ошибку. Приложение остаётся полностью рабочим без прокси: помощник — необязательный слой.

**Что уходит провайдеру.** Ровно то, что перечислено в блоке «Что уходит провайдеру» внутри панели: ревизии приложения и каталога, пресет, сеть и геометрия корпуса, число занятых и свободных модулей, разбивка по категориям и рядам, счётчики цепей и распределение токов по фазам, а также коды и заголовки сработавших проверок без их текстов.

**Что не уходит никогда.** Название и идентификатор проекта, адреса, маркировки, примечания, `instanceId` и `productId`, названия и артикулы аппаратов, названия цепей и нагрузок, подписи подключений, бинарные CAD-модели и тексты проверок. Сборка сводки находится в одном месте — `src/domain/assistantContext.ts`, а `tests/assistant-context.test.ts` и `tests/e2e/assistant.spec.ts` проверяют, что запрещённых значений в payload нет.

Предложения помощника не применяются молча: подписи кнопок собирает приложение, не модель; переход на другой корпус или рейку идёт через существующий диалог миграции; изменение настроек — обычная операция с отменой по Ctrl+Z. Перечень допустимых действий ограничен шестью: `cabinet.migrate`, `rail.migrate`, `settings.reserve`, `settings.inputCurrent`, `catalog.focus`, `rows.compact`. Всё остальное, включая неизвестные коды и выход значений за диапазон, отбрасывается с объяснением. Так как модель видит только сводку, предложения формулируются формой («корпус на 48 модулей в 4 ряда»), а конкретную позицию каталога выбирает приложение.

## 8. Будущий хостинг

При развёртывании статической сборки любой неизвестный путь приложения должен возвращать `index.html` (SPA fallback). Например, прямой запрос `/app/projects/<id>/editor` не должен возвращать HTTP 404. Ошибка должна возвращаться только для отсутствующих файлов вроде `/assets/missing.js`.

Примеры будущих правил:

- Nginx: `try_files $uri $uri/ /index.html;`
- Netlify: SPA redirect для всех маршрутов на `/index.html`;
- Vercel: filesystem-first rewrite всех прочих путей на `/index.html`.

До появления серверного слоя не добавляйте API routes, auth redirects или cookie-сессии, если они не покрыты отдельным threat model и тестами.

## 9. Чек-лист перед внешним показыванием

1. `npm run verify` завершён без ошибок.
2. На тестовом проекте открыты 2D, BOM, проверки и печать.
3. Создана и восстановлена резервная копия без локальных CAD-зависимостей.
4. Проверено, что неизвестная цена не превращается в коммерческий итог.
5. Проверено, что DEMO не создаёт пользовательские данные.
6. Пользователь предупреждён, что данные не синхронизируются и могут быть удалены вместе с данными браузера.
7. Если показывается ИИ-помощник: заполнен `tools/ai-proxy.env`, прокси запущен локально, а список отправляемых полей озвучен пользователю до первого вопроса.

## 10. Версия и выпуск

Версия приложения записана в коде в одном месте — `src/version.ts`. Из неё берутся `APPLICATION_REVISION`, поля `application.revision` и `applicationRevision` в конверте экспорта и подпись в подвале публичных страниц. Второе место, `version` в `package.json`, существует потому, что его требует npm; обычный модуль выбран вместо подстановки на этапе сборки, потому что версию читают Vite, Vitest и Playwright, и каждому конфигу пришлось бы описывать подстановку заново.

Рядом с версией приложения живут ревизии содержимого, каждая из которых сравнивается по своей шкале:

| Ревизия | Где | Что означает |
|---|---|---|
| `APP_VERSION` | `src/version.ts` | версия приложения, semver |
| `version` в `package.json` | корень | то же значение для npm |
| `PROJECT_SCHEMA_VERSION` | `src/domain/projectSchema.ts` | версия схемы проекта, целое |
| `CATALOG_REVISION` | `src/data/catalog.ts` | ревизия каталога, дата и номер |
| `VALIDATION_REVISION` | `src/domain/projectSchema.ts` | набор правил проверок, целое |

Файл, созданный более новой версией приложения, отклоняется при импорте — сравнение ревизий описано в разделе 4. При изменении схемы, каталога или правил проверок поднимайте минорную версию, иначе пользователь получит проект, который его сборка прочитать не сможет.

Порядок выпуска:

1. `npm run verify` завершён без ошибок.
2. `npm version <patch|minor>` обновляет `package.json`; затем то же значение ставится в `src/version.ts`.
3. Добавлен раздел в `CHANGELOG.md` с датой и списком изменений.
4. Коммит и тег: `git commit -am "release: <версия>"` и `git tag -a v<версия> -m "<версия>"`.

`tests/app-version.test.ts` падает, если версия в коде разойдётся с `package.json`, поэтому расхождение нельзя пропустить незаметно: тест входит в `npm test`, а значит и в `npm run verify`.

Репозиторий ведётся в git, удалённый репозиторий — `origin`. Ключ провайдера ИИ-помощника в коммиты не попадает: `tools/ai-proxy.env` исключён в `.gitignore`, а `tools/ai-proxy.env.example` содержит только placeholder.
