# ADR спайка A2: слоистая модель разводки

Дата: 17 октября 2026. Ветка `rework/spike-wiring`, проверяет решение D2 из
`docs/REWORK_PLAN.md`. Код: `src/domain/spike/` (терминалы, роутер и геометрия
сентябрьской линии, перенесённые изолированно) + `src/domain/spike/wiringLayers.ts`
(отображение октябрьского графа) + `tests/spike-wiring-layers.test.ts` (5 тестов,
все зелёные вместе с полным набором октября: 250).

## Вердикт

**Слоистая модель подтверждена с двумя уточнениями.** План Б (откат к октябрьской
семантике с поздним переносом роутера) не потребовался.

## По сценариям

**(a) Запитка от шины — подтверждено, с уточнением про L.** N/PE-подвод мапится в
соединение с `busId` именованной сборки; зажим существует (`clampExists`); роутер
сентября потребляет результат — smoke-тест рисует провода (`routeBoard` возвращает
непустые трассы). Уточнение: **фазного L-бара в сентябрьской модели нет** — сборки
существуют только для N и PE. Октябрьский `fromBus: 'L'` становится абстрактным
входом слева (ровно так же трактовала его миграция сентября v2→v3) или приходит
гребёнкой. Для единой схемы это решение: L-шина не становится BusAssembly.

**(b) Гребёнка — подтверждено.** Связи `busbar` между аппаратами ряда сохраняют
зажимы (`toTerminal`), инвариантность связности доказана тестом: множество пар
(устройство, зажим) одинаково до и после прохождения слоёв. Зажимы не заняты дважды.

**(c) Клеммная колодка — найдено главное трение.** У сентября `terminalColumns`
возвращает **0** для категорий `terminals` и `busbar`: колодка — не устройство с
колонками зажимов, её винты живут в механике `BusAssembly` (зажимы «варианта Б»).
У октября колодка — устройство, и `Connection.terminal` адресует её винты напрямую.
Отображение в `TerminalRef{pole, side}` даёт ссылку, которая зажима не находит —
тест фиксирует это как ожидаемое поведение.

**Решение для A4 (схема v5):** колодка остаётся устройством (габарит, BOM,
спецификация), но адресация её винтов — через зажимы сборки, как в сентябрьской
модели: `Connection` на колодку несёт ссылку на сборку/зажим, а не `pole/side`.
Проверочное правило октября «у колодки шесть винтов одной шины» сохраняется
в валидации, меняется только адресация.

## Второстепенные находки

- **Сторона зажима выводима из роли провода**: подвод (шина, гребёнка) входит
  сверху, линия цепи уходит снизу. Это совпадает с раскладкой `FacePocket`
  октября (`wiring.ts`, `makeTerminal` для обеих сторон). При A4 сверить
  дословно, правило отображения — в `wiringLayers.ts:toTerminalRef`.
- **Однополюсный автомат не имеет N-зажима** — в обеих моделях. N однофазной
  цепи уходит на колодку/шину, не на автомат (это же исправление описано в
  `BOARD_PLAN.md` для демо-проекта). Сценарии тестов скорректированы
  соответственно: N-подвод проверяется на двухполюсном УЗО.
- **Ручные изгибы (coderabbit) в спайк не входили.** Слой чисто аддитивный:
  переопределение геометрии при неизменном графе не может тронуть связность,
  которую охраняет инвариантность из теста (b). Переносится в A4 как отдельное
  необязательное поле соединения.

## Что переносится в A4 напрямую

- Тесты трёх сценариев — как регрессионные.
- Правило «L не является сборкой» — в миграцию v2→v5 и v4→v5.
- Адресация винтов колодки через сборку — в форму Connection v5.
